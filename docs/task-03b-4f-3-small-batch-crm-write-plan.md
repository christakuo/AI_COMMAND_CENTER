# Task 03B-4F-3：小流量 CRM 寫入驗收計畫與開關操作規格

## 1. 任務目標

本任務目標是建立小流量 CRM 寫入驗收計畫與開關操作規格，作為後續真正開啟健康評估 CRM 寫入前的操作準則。

本任務安全邊界：

- 本任務仍不開 CRM。
- 本任務仍不部署 Apps Script。
- 本任務仍不寫入 Google Sheet。
- 本任務仍不新增 referral_events。
- 本任務完成後，才可進入實際開關操作任務。

## 3. 是否需要部署第 21 版

判斷基礎：

- 03B-4F-1 只新增 Test.gs 測試函式。
- Test.gs 已同步線上並完成安全測試。
- 目前尚未部署第 21 版。
- 若下一階段只要開 CRM，必須確認目前線上 Web App 使用的版本是否已包含 03B-4E 正式邏輯。
- 第 20 版已包含 03B-4E 正式邏輯。
- 第 21 版是否必要，取決於是否要把 03B-4F-1 測試函式納入版本紀錄。

建議：

| 問題 | 建議 | 理由 |
|---|---|---|
| 若只是準備小流量 CRM 寫入，是否可以維持第 20 版？ | 可以 | 第 20 版已包含 03B-4E 正式 CRM 邏輯；03B-4F-1 只新增測試函式，不影響正式流程 |
| 若要保留完整測試函式版本紀錄，是否應建立第 21 版但保持 CRM false？ | 可以，但不是本任務執行項目 | 若團隊希望版本紀錄包含 Test.gs dry-run 矩陣，可建立第 21 版；仍必須保持 CRM false |
| Web App URL 是否可更換？ | 不可 | 必須更新現有 Web App 部署，不得建立不同正式 URL |

本文件建議：下一階段若要正式操作，先決定是否建立第 21 版；不論是否建立第 21 版，都不得更換 Web App URL。

## 4. CRM true 開關操作原則

- 只有在使用者明確確認後，才可將 HEALTH_ASSESSMENT_CRM_WRITE_ENABLED 改為 true。
- 開關改 true 必須建立新 Apps Script 版本。
- 必須更新現有 Web App 部署，不可新增不同 URL。
- 開 CRM 前必須再次確認回滾 SOP。
- 開 CRM 後第一批只允許內部手機測試。
- 開 CRM 後不新增 referral_events。
- 開 CRM 後不通知顧問。
- 開 CRM 後不發 LINE 主動訊息。
- 每筆測試後立即檢查 Sheet。
- 有任何異常立即改回 false 並部署回關閉狀態。

## 8. 開關操作流程草案

以下是後續實際開關任務的流程草案，本任務不執行。

1. 確認目前 Apps Script 第 20 版與 CRM false。
2. 確認測試資料就緒。
3. 確認回滾 SOP。
4. 修改 Config.gs：HEALTH_ASSESSMENT_CRM_WRITE_ENABLED=true。
5. 儲存。
6. 建立新版本。
7. 更新現有 Web App 部署，不更換 URL。
8. 執行 testHealthAssessmentCrmWriteDisabled，預期此時不再是 CRM_WRITE_DISABLED；若仍是 disabled，代表部署或版本未生效。
9. 執行第一筆內部小流量測試。
10. 檢查 health_assessments 與 leads。
11. 若正常，再執行下一筆。
12. 若異常，立即回滾。

注意：第 8 點可能需要另外設計 CRM true 專用安全測試，不應直接依賴 CRM false 測試。正式開關前應先確認要執行哪一個 CRM true 驗證函式。

## 9. 回滾判斷點

只要發生任一情境，就必須回滾：

- 產生錯誤 lead 歸屬
- 無效推薦碼寫入 leads 推薦碼
- 停止聯繫名單被恢復聯絡同意
- 已付款／已成交名單被改派
- 既有 lead 被自動改派
- referral_events 被新增
- Sheet 寫入欄位錯位
- Web App 回傳錯誤
- LINE 身分錯配
- 任何非預期新增 lead
